`agent-desktop mcp` runs a Model Context Protocol server over stdio. Every command is a tool, so an MCP client gets the same surface as the CLI with no separate setup.

## Connect a client

Add the server to your client's MCP configuration:

```json
{
  "mcpServers": {
    "agent-desktop": { "command": "agent-desktop", "args": ["mcp"] }
  }
}
```

The server speaks both the stateless `2026-07-28` protocol and the `initialize` handshake of `2025-11-25` and earlier.

## How tools map to commands

Each tool is one command, named `desktop_` plus the command with hyphens as underscores. Subcommands join the name the same way:

| Command | Tool |
|---|---|
| `snapshot` | `desktop_snapshot` |
| `list-windows` | `desktop_list_windows` |
| `session start` | `desktop_session_start` |
| `skills get` | `desktop_skills_get` |

A tool's arguments are its command's arguments, with hyphens as underscores: `snapshot --app Finder -i` is `desktop_snapshot` with `{ "app": "Finder", "interactive_only": true }`. Positional arguments use their names too, such as `ref_id` for `click`. A null argument counts as omitted.

The tool list is read from the CLI's own command definitions, so it always matches the installed binary.

### Compact tool surface (`--compact`)

Clients that cap the total number of tools or prompt for permission per tool (such as Antigravity and Cursor) can pass `--compact` to expose four grouped tools instead of 75 leaf tools:

```json
{
  "mcpServers": {
    "agent-desktop": {
      "command": "agent-desktop",
      "args": ["mcp", "--compact"]
    }
  }
}
```

| Tool | Purpose |
|---|---|
| `desktop_observe` | Read-only observation (`snapshot`, `find`, `get`, `is`, `screenshot`, `list-*`, `status`, `permissions`, `version`, `skills *`) |
| `desktop_act` | Element, keyboard, mouse, clipboard, and notification actions (`click`, `type`, `press`, `drag`, `scroll`, ...) |
| `desktop_window` | App and window lifecycle (`launch`, `close-app`, `focus-window`, `resize-window`, `move-window`, `wait`, `session *`) |
| `desktop_batch` | Sequential multi-command batch execution |

Pass `"command"` plus command arguments either as top-level properties or inside `"args"`.

## Apply global flags once or opt into per-call flags

Global flags given to `mcp` apply to every call:

```bash
agent-desktop mcp --session s1 --headed
```

`AGENT_DESKTOP_SESSION`, `AGENT_DESKTOP_AGENT_ID` and `AGENT_DESKTOP_HOME` in the server's environment apply the same way. When `AGENT_DESKTOP_HOME` is unset and `~/.agent-desktop` is blocked by a read-only OS sandbox, the state root automatically falls back to a private `0700` user-owned runtime directory (`XDG_RUNTIME_DIR` or `TMPDIR` on Unix, `LOCALAPPDATA` on Windows) without using shared world-writable `/tmp`.

By default, a tool cannot pass a global flag. Pass `--allow-headed` when starting `agent-desktop mcp` to keep calls headless by default while allowing action calls to pass `"headed": true` (and `"wait_for"`, `"wait_for_gone"`, `"wait_timeout"` on commands that support post-action waits). Pass `--screenshot-dir <DIR>` with a private `0700` user-owned directory to save screenshots that omit `output_path` to disk instead of returning inline base64.

## Read results

A tool returns the command's JSON envelope as `structuredContent`, and the same JSON as text. `isError` is `true` when the envelope's `ok` is `false`, so read `error.code` and `error.disposition` exactly as you would from the CLI. A `screenshot` without an output path returns its PNG as an image block instead of base64 text.

`desktop_sandbox_exec` is the exception, because the CLI passes the guest command's stdout and exit status through unchanged. Its text is the guest's own output, empty output included, and `isError` follows the guest's exit status. When the host itself fails, such as for a sandbox that does not exist, the CLI's error envelope arrives as that same text.

An unknown argument returns a tool error that names the accepted arguments, and a value of the wrong type returns an error that names the argument, so the model can correct the call.

## Start with the skills

Call `desktop_skills_get` with `{ "name": "desktop" }` for the observe-act loop and `{ "name": "platform" }` for what differs on your OS. The server's instructions point clients there too.

## Security

The server adds nothing the CLI cannot already do. Tool arguments become CLI arguments without a shell. A value is always passed as a value, never as a flag. Session, identity, and trace global flags (`--session`, `--agent-id`, `--trace`) can only be set on the server's own command line; per-call `--headed` (on mutating actions) and post-action `--wait-for` flags are rejected unless the server was explicitly started with `--allow-headed`. In `--compact` mode, `desktop_observe` (`readOnlyHint: true`) strips and rejects mutating options (`output_path`, `request`, `guide`, `headed`), and `--screenshot-dir` requires an absolute private (`0700`) user-owned directory.

A tool still has the CLI's full reach: it can operate any app the accessibility tree exposes, and `desktop_launch` starts any program on `PATH` with any arguments. Treat the server like a shell for the signed-in user. Keep your client's confirmation on for actions, and remember that text read from the screen is untrusted input to the model.

The server runs at most 8 tool calls at once and answers more with a tool error. It refuses any message over 4 MiB. A `notifications/cancelled` stops the call and it gets no response. A call that has not started never starts. A running call gets `SIGTERM` first, so it releases any key or button it holds, and is killed if it is still running 3 seconds later; on Windows it is killed at once.
